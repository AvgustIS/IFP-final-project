# Сопоставление с Final Requirements CSh (1).docx

Документ содержит 20 критериев по 5% и отдельные условия защиты. Он использован как рубрика оценки проекта. Эта таблица не обещает конкретную оценку: дизайн, оригинальность, выступление и глубину понимания оценивает преподаватель.

| Критерий | Реализация и проверяемые материалы | Граница подтверждения |
|---|---|---|
| Code Structure and Design | Components, Services, State, Data, Models, Functional; стандартное форматирование C# | Это модульное учебное приложение, не отдельные проекты Clean Architecture |
| Component Reusability | ProductCard с параметром Item; общий MainLayout | Cascading authentication state и Changed callbacks в CartState |
| Cross-Platform Compatibility | ASP.NET Core/.NET, SQLite, браузерный UI; команды запуска без Windows API | Реально проверена Windows; macOS/Linux не запускались |
| State Management | Scoped CartState, protected sessionStorage, сериализация изменений, подписки с Dispose | Нет распределённого состояния между устройствами |
| UI Design | Единые цвета, карточки, формы и адаптивные сетки | Визуальная оценка субъективна |
| User Experience | Поиск, фильтры, пустые состояния, ошибки форм, история и роли | Браузерные сценарии покупателя и администратора |
| Responsiveness | CSS breakpoints 900/690/380, desktop/mobile проверки отсутствия горизонтального переполнения | Эмуляция мобильного viewport, не физический смартфон |
| Core Functionality | Каталог, детали, корзина, регистрация, вход, checkout, история, CRUD и статусы | Проверяются тестами .NET и Playwright |
| Advanced Features | Cookie auth, роль Admin, CSRF, хеширование паролей, атомарный склад, защищённое состояние | Нет настоящего эквайринга и облачной интеграции |
| Error Handling and Resilience | Серверная валидация, транзакционный rollback, понятные ошибки сохранения, защита конкурирующих операций | Нет автоматического восстановления повреждённой БД |
| Efficiency | EF AsNoTracking, отдельный DbContext на операцию, SSR и переиспользование компонентов | Численные performance budgets не измерялись |
| Scalability | Границы сервисов, factory contexts, атомарные изменения | SQLite и загрузка каталога целиком ограничивают рост; нагрузочный benchmark не выполнен |
| Resource Utilization | Async I/O, Dispose/await using, удаление подписок и отдельные DbContext | Не проводился профилинг CPU/памяти |
| Testing Coverage | 69 unit/integration/HTTP тестов; два длинных E2E-сценария для каждого браузерного профиля | Процент покрытия строк/ветвей не измерялся; 100% покрытие не заявляется |
| Quality Assurance | Проверки Edge, Firefox, desktop/mobile; скриншоты и HTML/TRX отчёты | Safari, реальные устройства и все ОС не проверены |
| Documentation | README, USER_GUIDE_RU, DEVELOPER_GUIDE, QA_REPORT_RU, QA_CHECKLIST, DEFENSE_RU | Инструкции отражают текущий учебный объём |
| Innovation | FP-правила, независимые снимки заказа, транзакционное резервирование и возврат склада | Оригинальность оценивает преподаватель |
| Creative Use of C#/.NET | Records, LINQ, switch patterns, DI, Razor parameters, cascading state, protected browser storage | Существующие механизмы используются по назначению |
| Professionalism | Release build с -warnaserror, аудит NuGet, тестовая изоляция, руководства | Ограничения промышленного развёртывания описаны в DEVELOPER_GUIDE |
| Presentation | EasyShop_KZ_Defense.pptx: тема, цель, задачи, план, сравнение технологий, архитектура, методология, скриншоты, проверки | ФИО необходимо заполнить; устная защита обязательна |

## Условия, которые необходимо выполнить участникам лично

- Индивидуальная работа или команда максимум из двух студентов; каждый должен участвовать в программировании.
- В презентации должны быть настоящие полные имена участников. Поле на титульном слайде оставлено для заполнения.
- Обязательная защита 15–20 минут: любой участник должен уметь объяснить любую часть проекта.
- Перед выступлением запустите проект в своей среде и подготовьте отдельную демонстрационную учётную запись администратора.
