Тестовые данные изолированы: HTTP-тесты создают временные БД; E2E и smoke используют отдельные файлы в artifacts. Обычная база магазина не использовалась. Локальные тестовые серверы после проверки остановлены.

## Что исправлено

1. Удалены недопустимые точки с запятой после auto-properties, устранён конфликт имени компонента Cart и внедрённого сервиса.
2. Добавлены недостающие Razor namespaces и RenderMode imports, восстановлена рабочая маршрутизация.
3. Корзина переведена с хранения только в circuit на ProtectedSessionStorage: переживает refresh и вход в той же вкладке.
4. Cart/Checkout подписываются на изменения состояния и снимают подписки. Восстановленная корзина обновляет страницу и счётчик.
5. Изменения корзины сериализованы, сохранение выполняется до публикации изменения. Добавление большого количества не переполняет int.
6. При отмене заказа предыдущий статус проверяется атомарным UPDATE внутри транзакции до возврата склада: две отмены не возвращают запас дважды.
7. Начало checkout-транзакции входит в обработку ошибок, проверяется существование пользователя. Тесты подтверждают rollback и невозможность купить последнюю единицу дважды.
8. Инициализация не восстанавливает удалённые администратором товары, если каталог уже создан, и не предполагает наличие четырёх категорий в частично заполненной базе.
9. Усилены серверные проверки цены, URL изображения и длины email; пустой URL при редактировании получает стандартное изображение. Цена в админке допускает два десятичных знака.
10. Неверный или отсутствующий antiforgery token возвращает 400; ошибки сохранения связанных/изменённых записей дают понятное сообщение.
11. Login/Register исключены из интерактивной маршрутизации: cookie-формы отправляются обычным HTTP POST. Элементы остальных страниц доступны после готовности circuit, что предотвращает сброс раннего ввода в Firefox.
12. Уточнена доступная подпись Category в админке. Обновлены EF Core/тестовый ASP.NET Core до 10.0.12 и SQLitePCLRaw bundle до 3.0.5; убрана избыточная Identity-ссылка.
13. Расширены тесты, обновлены инструкции, добавлены руководства, сопоставление с рубрикой и редактируемая презентация.

Изначальное предупреждение SQLite подтверждалось [GitHub Advisory GHSA-2m69-gcr7-jv3q](https://github.com/advisories/GHSA-2m69-gcr7-jv3q). Финальный вывод об отсутствии известных уязвимостей относится к выполненному NuGet-аудиту и не является обещанием отсутствия любых ошибок безопасности.

## Проверенные сценарии

- Чистые функции: неизменяемые обновления, суммы, ограничения склада, нулевое количество, переполнение, поиск, категории и сортировка, переходы статусов.
- Сервис и SQLite: CRUD товаров/категорий; валидация; checkout с ценой из БД; откат нескольких позиций; отсутствующие товары/пользователи; история по пользователю; снимки удалённого товара; завершение и отмена.
- Отдельные подключения SQLite: конкурирующие покупки и отмены, повторное открытие базы, повторная инициализация каталога.
- HTTP: публичные страницы, статические файлы, регистрация, дубликаты email, неверный/верный пароль, cookies, logout, CSRF, права Customer/Admin.
- Браузер: поиск/фильтры/сортировка/reset, детали, добавление/количество/удаление, refresh корзины, регистрация/вход, валидация доставки, наличная и Demo Card, заказ, история после refresh, запрет просмотра чужого заказа, logout, несуществующий товар, CRUD админки, обработка и отмена заказа, возврат остатка и сохранение снимка после удаления.

## Повторение и артефакты

```powershell
dotnet test EasyShop.sln --configuration Release --verbosity minimal --logger trx --results-directory artifacts/test-results -warnaserror
cd tests/e2e
npm.cmd ci
npx.cmd playwright install msedge firefox
npx.cmd playwright test
```

Для браузерных тестов также нужна актуальная Debug-сборка, поскольку webServer запускается с `--no-build`: выполните `dotnet build EasyShop.sln` из корня, если Debug ещё не собран. На Linux/macOS команды npm/npx пишутся без `.cmd`.

- `artifacts/test-results/*.trx` — машинный отчёт .NET.
- `tests/e2e/playwright-report/index.html` — последний HTML-отчёт Playwright.
- `tests/e2e/test-results/.last-run.json` — status passed, failedTests пуст.
- `artifacts/*-catalog.png`, `*-dashboard.png`, `*-admin.png` — скриншоты браузерных проверок.
- `artifacts/publish-smoke.log` — журнал запуска опубликованной версии.
- `docs/EasyShop_Defense.pptx` — актуальная презентация, предоставленная пользователем; 11 слайдов.

## Что проверка не подтверждает

Не выполнялись запуск на macOS/Linux, Safari и реальных мобильных устройствах, аудит screen reader, нагрузочное тестирование, профилирование и измерение процента покрытия. Это учебный магазин: оплата имитируется, нет password reset/verification и промышленного identity provider. Денежные колонки сохраняют исходное double-хранение для совместимости схемы; перед финансовым production требуется миграция к точным минимальным единицам.

Соответствие 20 пунктам рубрики разобрано в REQUIREMENTS_RU.md. Устную защиту, личное участие участников и итоговую оценку нельзя подтвердить программными тестами. На титульном слайде необходимо заполнить настоящие полные имена участников.
